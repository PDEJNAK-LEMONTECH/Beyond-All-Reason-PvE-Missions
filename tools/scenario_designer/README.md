# BAR Scenario Designer

A visual, point-and-click **map-editor-style** planner for the scripted-PvE **Mission API**
(see `../../MISSION_API.md`). Pick a map, lay out the AI base and spawn points, draw trigger
areas and barriers, wire triggers to actions — then export a ready-to-run mission `.lua` (and a
launchable scenario-menu file). It runs as a plain offline web app — **no server, no install,
no engine** — just double-click `designer.html`.

```
tools/scenario_designer/
  prepare_assets.ps1   one-time: builds map thumbnails + the unit list  -> data.js
  designer.html        the app (open this)
  designer.css         styles
  designer.js          logic (canvas editor, schema forms, Lua import/export)
  data.js              GENERATED by the prep script (maps + units)
  maps/                GENERATED minimap thumbnails
```

## 1. One-time setup — run the prep script

The designer needs each map's **true dimensions** (so it can draw with correct proportions,
never stretched) and a minimap image. Both come from your installed BAR. Run, from the repo:

```powershell
& "C:\PROJ\BAR\tools\scenario_designer\prepare_assets.ps1"
```

What it does:
- extracts the **DXT1 minimap embedded in every map's `.smf`** via 7-Zip and decodes it to a
  thumbnail (works for all maps, regardless of whether they ship a `mini.png`);
- reads the real world size in elmos from the `.smf` header (`mapx`/`mapy` × 8) — this is what
  makes the overlay's aspect ratio exact;
- pulls human-readable **map names** from the engine's `ArchiveCache`, and **unit names** from
  `language/en/units.json`;
- writes `data.js` + thumbnails into `maps/`.

Re-run it whenever you install new maps. Flags: `-DataDir`, `-SevenZip`, `-ThumbSize`,
`-SkipExistingThumbs` (reuse existing thumbnails, just refresh dimensions/names).

Requirements: 7-Zip (auto-detected at `C:\Program Files\7-Zip\7z.exe`) and an installed BAR.

## 2. Use the designer

**Two ways to open it:**
- **`start_server.cmd`** (recommended) — double-click it. It starts the tiny local server, opens
  the app at `http://localhost:8777/designer.html`, and **enables the one-click ▶ Test Play
  button** (a plain `file://` page can't launch the game; the local server can). A tray icon
  appears while it runs — right-click it to stop, or just close the console window.
  - This is just a wrapper that runs `serve.ps1` with `-ExecutionPolicy Bypass`. Use it because
    Windows' default PowerShell policy is `Restricted`, so double-clicking `serve.ps1` directly
    (or running `.\serve.ps1`) dies instantly — *"running scripts is disabled on this system"* —
    with no tray icon. The `.cmd` sidesteps that and keeps the window open if anything errors.
  - Prefer to fix it permanently instead? Run once: `Set-ExecutionPolicy -Scope CurrentUser
    RemoteSigned`. Then `serve.ps1` / the desktop shortcut work directly.
  - Arguments are forwarded: `start_server.cmd -Port 9000`, `start_server.cmd -DryRun`, etc.
- **`designer.html`** / **`launch.ps1`** — open it directly from disk (`file://`). Everything
  works except Test Play, which falls back to downloading a start script.

If anything goes wrong at runtime, a red error banner appears at the top of the page with the
details (rather than failing silently).

1. **Launch screen** — search and click a map. (Or *Open existing scenario…* to jump straight
   into editing one.)
2. **Place things** with the toolbar tools (hotkeys in parentheses):
   - **Select (V)** — click to select; drag handles to move. **Right-drag or hold Space to pan;
     mouse-wheel to zoom.**
   - **Player start (1)** / **AI spawn (2)** — where commanders begin (written into the scenario
     start script as fixed `StartPos`).
   - **Building (3)** — pre-place an AI base building. Pick the unit in the left *Placement*
     panel first, set its owner role + facing, then click to drop (drop several).
   - **Trigger area (4)** — drop a circular `UnitEnteredLocation` trigger; drag the centre to
     move, the edge handle to resize.
   - **Barrier (5)** — click start then end to lay a `SpawnBarrier` line (Dragon's Teeth, etc.).
   - **Spawn point (6)** — drop a `SpawnUnits` action point.
3. **Triggers & Actions** (right panel) — add any trigger/action type, edit its parameters in the
   **Inspector**, and in a trigger tick the actions it should **fire**. Spatial parameters
   (x/z/radius, barrier endpoints) are editable both in the form and by dragging on the map.
4. **Setup** (left panel) — choose which roles start **frozen** (dormant), and fill in title /
   briefing / difficulty / **team defeat condition**.

   The **"When is a player/AI eliminated?"** dropdown sets the engine's `deathmode` modoption per
   scenario (baked into both the exported scenario-menu start script and the downloadable start
   script). It controls when an *individual* player/AI is removed (its units destroyed) — and it
   applies to **all** players, the human included:
   - **When their own Commander dies** (`own_com`, **default**) — kill an AI's commander and *that
     AI* is eliminated immediately, buildings and all, while any other commanders keep playing.
     This is the classic "com death = you're out" rule most scenarios want.
   - **When all their units are destroyed** (`killall`) — every last unit must die.
   - **Only when their whole alliance loses every Commander** (`com`) — alliance-wide: a side
     survives (buildings stay) until the *last* commander across its entire allyTeam dies. (This
     is the engine's global default and the reason commander kills left buildings standing.)
   - **Never** (`neverend`) — the engine never eliminates anyone; drive win/lose entirely with
     Mission API `Victory`/`Defeat` actions. Use this for fully scripted or asymmetric rules.

### Saving / launching

- **Save mission .lua** → download the mission file. Put it in
  `singleplayer/missions/<name>.lua`. This is the file the Mission API loads via the
  `mission_path` modoption. Coordinates are written as **absolute world elmos** for the chosen
  map.
- **Export scenario menu** → download a `singleplayer/scenarios/scenarioNNN.lua` that bakes in
  the map, the player/AI start positions, one BARb AI per AI spawn, and `mission_path` — so the
  scenario shows up under **Single Player → Scenarios** and launches straight in. (Add a matching
  `scenarioNNN.jpg` if you want a thumbnail. Drop a `.jpg` next to it.)
- Iterate on logic in-game with **`/luarules reload`**; `Setup`/base changes need a match
  restart.

### ▶ Test Play (one click)

When the designer is opened via **`serve.ps1`**, the **▶ Test Play** button:
1. writes the mission to `singleplayer/missions/<name>.lua` in the repo,
2. builds an engine start script (your map, player + AI start positions, one BARb per AI,
   `mission_path` set, `gametype` taken from your last dev launch's `_script.txt`),
3. launches `spring.exe` straight into the match — no lobby, no menu.

Opened from `file://` instead, Test Play (and the **⬇ Start script** button) downloads a
ready-to-run start script you can launch manually:
`spring.exe --write-dir "<data>" play_<name>.txt`.

The **Inf LOS** checkbox next to ▶ Test Play is a debug aid: when ticked, the generated
start script sets the `mission_debug_los` modoption, which reveals the whole map (global
line-of-sight) for the human side so you can watch the entire scenario play out. It only
affects launches made while it's checked — it isn't saved into the mission/scenario files —
and has no effect outside scenarios.

> For **multiplayer**, the same exported start-script block is what you host with (see
> `../../MULTIPLAYER_HOST.md` / `tools/StartScripts/pve_host.txt`). Both PCs must run the same git
> commit.

### Editing existing scenarios

- Files **saved by this designer** round-trip perfectly: each mission file carries a
  `--[==[ SCENARIO_DESIGNER_V1 … ]==]` comment block with the full layout (positions, links,
  metadata). *Open…* reads it back exactly.
- **Hand-written** scenarios (e.g. `pve_demo.lua`) are imported best-effort by a small built-in
  Lua reader that understands the scenario format, including `local` arithmetic and
  `Game.mapSizeX/Z`. **Tip:** pick the scenario's intended map first, *then* File → **Open** — so
  proportional coordinates resolve against the right map size. Verify positions after import.

## Diagnostics / logging

If anything misbehaves, the app keeps a diagnostic log so it can be inspected after the fact:
- A red **error banner** appears at the top of the page on any runtime error (with stack); render
  errors are caught and logged rather than blanking the screen.
- **🐞 Log** button (top bar) or **Ctrl+Shift+L** (works anywhere, even the launch screen)
  downloads `bar-designer-log.txt` — boot sequence, chosen map, canvas size, image loads, errors.
- The last ~400 log lines also persist to `localStorage` (`barDesignerLog`) across reloads.
- Appending `#autotest` to the URL makes the app auto-open the first map on load (used for
  headless screenshot testing).

## How "proper proportions" works

A map's embedded minimap is always a **square** 1024×1024 image, but maps aren't square. The prep
step records each map's true `width:height` (from the `.smf`), and the canvas draws the square
minimap into a rectangle of that true aspect ratio — un-squishing it. All editing happens in real
world coordinates (elmos), so what you place is exactly where it lands in-game.
